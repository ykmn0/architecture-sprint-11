## 2. Роадмап изменений

### Роадмап (этапы):

| Этап                                      | Описание изменений                               | Ресурсы и команды                          | Результаты                                       |
|-------------------------------------------|-------------------------------------------------|-------------------------------------------|-------------------------------------------------|
| **Этап 1: Миграция на Snowflake**         | Перевод DWH на Snowflake для более гибкого масштабирования и обработки больших данных | Команда DevOps, системный архитектор       | Более гибкое и масштабируемое хранилище данных, улучшение производительности отчетности |
| **Этап 2: Внедрение Kafka для интеграции**| Переход на Kafka для улучшения обработки данных в реальном времени и интеграции сервисов | Команда интеграции, инженеры по данным    | Улучшение синхронизации данных между сервисами и повышение скорости обработки в реальном времени |
| **Этап 3: Переход на микросервисную архитектуру с использованием Go** | Разработка микросервисов на Go для повышения производительности и масштабируемости | Команда разработки, системный архитектор | Микросервисная архитектура с высоким уровнем масштабируемости и улучшением производительности |
| **Этап 4: Внедрение Event-driven architecture** | Переход на архитектуру, основанную на событиях, для улучшения реактивности и масштабируемости | Команда DevOps, системный архитектор        | Повышение гибкости системы, снижение зависимости между компонентами |
| **Этап 5: Внедрение автоматизации тестирования с использованием Cypress** | Автоматизация тестирования для ускорения выпуска продуктов и улучшения качества | Команда тестирования, разработчики        | Ускорение процесса тестирования и улучшение качества программного обеспечения |

## 3. Обоснование изменений

1. **Миграция на Snowflake**:
   - **Зачем**: Snowflake предлагает лучшие возможности для масштабируемости и обработки больших объёмов данных, что критично для компании с растущими объёмами данных в DWH. Это также позволит улучшить гибкость хранилища, особенно с учётом интеграции с другими сервисами и аналитическими платформами.
   - **Ресурсы**: Команда DevOps и системные архитекторы для настройки и миграции данных.
   
2. **Внедрение Kafka**:
   - **Зачем**: Использование Kafka для обмена данными в реальном времени между микросервисами значительно ускорит обработку данных и улучшит взаимодействие между сервисами. Это также позволит интегрировать новые сервисы и улучшить реактивность системы.
   - **Ресурсы**: Команда интеграции и инженеры по данным для настройки и поддержки Kafka.
   
3. **Переход на микросервисную архитектуру с использованием Go**:
   - **Зачем**: Go идеально подходит для разработки высокопроизводительных и масштабируемых микросервисов, что нужно для системы, которая будет работать с большими объёмами данных и поддерживать высокую нагрузку.
   - **Ресурсы**: Команда разработки и системный архитектор для миграции на микросервисную архитектуру.
   
4. **Внедрение Event-driven architecture**:
   - **Зачем**: Эта архитектура позволит более эффективно управлять событиями в системе, улучшит реактивность и масштабируемость. Переход на Event-driven архитектуру сделает систему более гибкой и готовой к будущим изменениям.
   - **Ресурсы**: Команда DevOps и системный архитектор для внедрения Event-driven подхода.
   
5. **Автоматизация тестирования с использованием Cypress**:
   - **Зачем**: Cypress позволяет автоматизировать тестирование фронтенда и улучшить качество программного обеспечения. Автоматизация тестирования поможет ускорить процесс релиза и повысить надёжность кода.
   - **Ресурсы**: Команда тестирования и разработчики для настройки и использования Cypress.
