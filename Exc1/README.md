# Архитектура системы через год

## Комментарии к диаграмме контейнеров в модели C4:

### 1. **Портал самообслуживания (Data Portal)**:
- Это веб-приложение, которое будет являться основным интерфейсом для бизнес-пользователей, обеспечивая возможность создания отчётов и доступ к данным. Пользователи смогут выбирать срезы данных в зависимости от своего уровня доступа.
- **Технологии**: Web Application, API.

### 2. **Data Warehouse (DWH)**:
- Это основное хранилище данных, которое будет продолжать функционировать, но с минимальной бизнес-логикой, обеспечивая консистентность и надёжность хранения данных для дальнейшей аналитики. Для этого потребуется больше параллельной обработки и данных в реальном времени.
- **Технологии**: Microsoft SQL Server, Hadoop, Apache Spark (для обработки больших данных).

### 3. **BI-система (Business Intelligence)**:
- Это система для визуализации данных, которая будет использовать данные из DWH и интегрироваться с порталом самообслуживания. BI-система обеспечит создание отчётов, панелей и дашбордов.
- **Технологии**: Power BI, Tableau.

### 4. **ИИ-сервисы (AI Services)**:
- Сервисы для обработки и анализа медицинских данных, использующие ИИ для диагностики и улучшения качества лечения.
- **Технологии**: Python, TensorFlow, PyTorch.

### 5. **Финтех-сервисы (Fintech Services)**:
- Сервисы для предоставления финансовых услуг, работающие с финансовыми данными, счётами, кредитами и прочими финансовыми аспектами бизнеса.
- **Технологии**: Golang, Java, API для взаимодействия с DWH и другими сервисами.

### 6. **Интеграционная шина (Integration Bus)**:
- Шина для интеграции всех систем и сервисов. Это будет центральное место для обработки и синхронизации данных между различными сервисами и бизнесами. Шина обеспечит обмен данными между DWH, BI-системой, ИИ-сервисами и финтех-сервисами.
- **Технологии**: Kafka, RabbitMQ.

### 7. **Внутренние сервисы (Internal Services)**:
- Это внутренние сервисы компании для управления данными, включая управление пользователями, данными клиентов, персоналом и прочими внутренними процессами.
- **Технологии**: REST API, PostgreSQL.

## Проблемные места

1. **Масштабируемость DWH**:
   - DWH на базе SQL-сервера может не справляться с ростом объёма данных и сложностью отчётов, особенно с учётом новых интеграций.
   - **Решение**: Рассмотреть возможность миграции на распределённые хранилища данных (например, Hadoop, Spark) для более эффективной обработки больших данных.

2. **Сложность интеграции новых бизнесов**:
   - Интеграция новых сервисов, например, фармацевтических компаний или производителей медицинского оборудования, требует значительных усилий, особенно если необходимо поддерживать старую бизнес-логику в DWH.
   - **Решение**: Разделение логики и данных через интеграционную шину и переход на более гибкую архитектуру, например, микросервисы и Event-driven подход.

3. **Зависимость от легаси-систем**:
   - Существующие системы, такие как Power Builder и SQL Server, могут существенно тормозить внедрение новых бизнес-решений.
   - **Решение**: Постепенная миграция на современные платформы и отказ от устаревших технологий (например, от Power Builder).

4. **Прозрачность и доступность данных**:
   - Витрина данных должна быть доступной и масштабируемой, а текущая система может иметь ограничения по созданию отчётов и доступу к данным для пользователей.
   - **Решение**: Использование современных решений для визуализации данных, улучшение доступа через веб-портал с возможностью самоконструирования отчётов.

5. **Сложности с обработкой данных в реальном времени**:
   - Обработка данных в реальном времени, особенно с учётом ИИ-сервисов, может быть сложной из-за необходимости быстро интегрировать большие объёмы данных.
   - **Решение**: Интеграция с системами потоковой обработки данных (например, Kafka, Flink).

## Приоритизация проблем (метод MoSCoW)

1. **M (Must have)**:
   - Разделение данных по бизнес-доменам и обеспечение масштабируемости через новые сервисы.
   - Миграция от легаси-систем для повышения скорости работы и масштабируемости.

2. **S (Should have)**:
   - Разработка портала самообслуживания для пользователей с улучшением доступности данных.
   - Интеграция с новыми бизнесами через гибкую интеграционную шину.

3. **C (Could have)**:
   - Использование машинного обучения для оптимизации работы с данными и улучшения рекомендаций в BI-системе.

4. **W (Won’t have)**:
   - Ожидание полной миграции всех систем в течение года. Миграция старых технологий, таких как Power Builder, будет более долгосрочной задачей.
